# LearnMate 产品需求文档

## 1. 文档定位

本文是 LearnMate 产品需求的唯一维护入口，统一记录产品目标、学习场景、功能要求、设计约束与验收场景。

本文描述产品方案，不代表功能已实现，也不将完整方案直接等同于首版开发范围。文中明确的产品方向与约束作为设计依据，待明确事项不视为已确认决策。

对应赛事为揭榜挂帅赛题 `JBGS-2026-02`，官方要求、评分标准及参赛交付物见 [competition.md](competition.md)。验收场景用于检查产品需求是否满足；任务编排与进度由 GitHub Issues 管理，并引用本文相关章节。具体实现选择及其讨论记录在相关 Issue 或 PR 中；涉及产品需求的已确认变更同步更新本文。

## 2. 产品背景与目标

开发一款面向 K12 阶段学生的多模态人工智能通识课学习产品，将 AI 定位为长期陪伴式的“学习搭子”。系统持续理解学生的年龄、年级、知识基础、兴趣偏好和实际学习表现，为不同学生组织不同深度、表达方式和交互形式的教学内容。

产品应形成以下闭环：

了解学生 → 组织教学 → 互动练习 → 学习评估 → 更新画像与学习状态 → 调整后续教学。

个性化需要体现在教学内容深度、交互形式和后续学习安排上。课程、自由探索、练习和实验共享学生模型，使 AI 能够持续判断学生已经掌握什么、存在哪些困难，以及下一步适合学习什么。

## 3. 目标用户与学段适配

目标用户为小学至高中阶段学习编程与人工智能通识知识的学生。

- 小学阶段侧重故事、图片、拖拽、选择和可视化实验。
- 初高中阶段逐步增加代码编辑、运行、调试，以及算法和参数实验。
- 年龄、年级、已有基础、兴趣与学习表现共同影响教学安排，不能仅按年龄划分固定内容。
- 兴趣用于选择教学情境和案例，不改变知识本身的科学内容。

## 4. 学生模型与初次建档

### 4.1 轻量建档

学生首次进入系统，通过自然对话和少量轻量诊断任务完成初步建档，避免要求学生填写大量表单。

对话可了解当前年级、编程或人工智能接触经历、兴趣，以及对图片、故事、互动、动手实践等学习形式的偏好。穿插简单问题，对知识基础进行初步判断。

### 4.2 模型组成

| 组成 | 记录内容 | 教学用途 |
| --- | --- | --- |
| 相对稳定的学生画像 | 年龄、年级、兴趣、学习形式偏好等 | 选择语言风格、案例和教学媒介。 |
| 持续变化的学习状态 | 具体知识点掌握程度、常见错误、答题表现、提示需求、教学方式适配表现等 | 决定下一步学习、复习内容与难度调整。 |

学生模型随实际学习持续更新。掌握程度的判断应依据学习证据，不能仅依赖大模型主观判断。

## 5. 主要学习场景

完成建档后，学生可进入“课程学习”或“自由知识探索”，并进一步进入 AI 实验室进行实践。各场景共享学生模型、知识库与 AI 教学引擎，学习结果共同影响后续教学。

### 5.1 课程学习

课程承担系统化教学任务，以教材、既定课程体系和知识库为基础，将课程拆分为明确的知识点与学习关卡，以游戏化学习路径组织新知识学习、练习、复习和实践。

课程知识点、前置关系、学习目标和课程顺序应提前确定。AI 在稳定的知识结构上编排具体教学内容，不能完全自由决定课程知识结构。

#### 分页课堂

- 采用类似 PPT 的分页教学形式。
- 每页由标题、文字、图片、文本框、代码、简单图示等基础教学组件构成。
- 配合 AI 生成或预制的语音讲解，页面内容与讲解同步推进。
- AI 从预设布局和教学组件中选择形式、填充内容，避免自由生成复杂页面造成不稳定。

#### 互动练习

规划支持单选、多选、判断、文字回答、语音回答、拖动分类、拖动排序、连线匹配和编程练习。

AI 根据知识点、学生掌握情况与教学目标生成题目内容和组件配置，前端通过标准组件呈现。例如，学习“训练数据”时，小学生可拖动猫狗图片进行分类，高中生可进入代码或参数实验。

核心交互以标准练习组件为基础，不依赖复杂视频生成。

#### 动态教学过程

采用“稳定知识骨架 + 动态教学生成”的方式：

1. 根据当前知识点规划本节课的教学目标与知识节点。
2. 逐步生成页面和互动任务，并提前缓存后续内容。
3. 根据学生的新行为调整尚未生成的部分。
4. 连续答对且掌握较好时，适当缩短解释、提高练习难度。
5. 连续出错时，插入新例子、图示、基础练习，必要时回退到前置知识。

学生进入课堂前无需一次性生成完整课程；动态调整应保持既定知识结构与教学目标。

#### 课堂打断与恢复

学生可随时通过文字或语音打断 AI 提问。系统需维护当前知识点、页面、教学目标与中断位置。

- 与当前内容相关：暂停主课程，针对性解释，确认理解后回到原教学位置。
- 属于后续知识：简短回应，引导学生稍后学习。
- 与课堂关系较弱：保存为后续探索主题，避免无限偏离课堂主线。

形成“课堂推进 → 学生打断 → 针对性答疑 → 回归课堂”的有状态教学过程。

### 5.2 自由知识探索

满足学生课外好奇心和临时知识需求，以可上下滚动的动态讲义呈现内容，支持回看和追问。

- AI 先理解真实意图，再决定简短答疑或组织微课程。
- 简单概念问题直接回答。
- 系统性学习需求先规划主题结构，再逐步生成标题、文字、图片、知识卡片、示例和互动问题。
- 学生可边听讲解、边浏览内容，并随时回看、追问。
- 内容仍根据年龄、知识基础与兴趣组织。
- 记录兴趣方向、知识掌握情况与知识缺口，并与正式课程建立联系，必要时推荐课程、练习或实验。

例如，对喜欢足球的学生，可用运动员位置分类解释分类算法，同时保持概念的科学准确性。

### 5.3 AI 实验室

实验室用于通过动手实践理解人工智能知识，并尽可能与课程知识点打通。

- 围绕图像分类、KNN、神经网络、Prompt 等概念提供对应实验。
- 支持通过修改参数、观察模型输出、运行代码或完成简单任务理解知识。
- 小学阶段以拖拽、选择、可视化实验为主；初高中逐步增加代码编辑、运行和调试。
- 实验结果作为学习证据写入学习状态，影响后续课程推荐。

## 6. 学习评估与自适应路径

### 6.1 学习证据

将实际行为记录为结构化学习事件，包括答题正误、尝试次数、提示使用情况、完成时间、代码运行是否成功，以及是否频繁询问某个概念等。

课程、自由探索、练习和实验的事件汇入同一学生模型，用于更新具体知识点的掌握程度和常见误区。

### 6.2 路径调整

- 已掌握较好的知识点：减少重复教学，进入更高阶内容。
- 基础知识存在明显缺口：临时插入补充关卡。
- 学过但可能遗忘的内容：安排复习任务。

学生的课程地图根据学习状态调整，形成“新知识学习 → 互动练习 → 实践实验 → 效果评估 → 个性化复习 → 继续学习”的闭环。

## 7. 知识准确性与教学约束

- 建立由教材、课程资料和经过整理的内容组成的知识库，并按知识点检索。
- 正式课程核心知识应有知识库依据，不能完全依赖大模型自身记忆。
- 知识库确定应该讲什么；大模型根据学生情况决定怎样讲。
- 核心练习和标准答案优先采用预生成、审核或可校验的方式保证可靠性。
- 动态题目生成更多用于个性化巩固和补充练习。
- 各学习场景共享学生模型与教学决策，避免学习证据分散、无法影响后续教学。

## 8. 方案中的系统职责

以下职责划分用于约束产品协作方式，不指定技术栈或具体代码实现。

| 职责 | 输入或处理 | 结果 |
| --- | --- | --- |
| AI 教学引擎 | 当前知识点、学生模型、课程目标、知识库内容 | 教学规划，以及由展示组件和互动组件组成的课程结构。 |
| 前端呈现 | 教学结构和组件类型 | 分页课堂、动态讲义、练习与实验交互。 |
| 语音交互 | AI 讲解与学生语音输入 | 配合页面的语音教学与提问。 |
| 学习事件记录 | 各场景中的实际学习行为 | 可用于评估的结构化学习证据。 |
| 学习评估 | 学习事件与学生学习状态 | 更新学习状态，调整下一阶段课程内容和学习地图。 |

## 9. 验收场景

以下场景用于检查产品行为，不规定量化性能指标，也不替代赛事验收要求。

| 场景 | 可观察的完成标准 |
| --- | --- |
| 初次使用 | 通过自然对话与少量诊断建立初始学生模型，无需大量表单。 |
| 学段与基础适配 | 对同一知识点，不同学段或基础的学生得到适合的知识深度、语言与交互形式。 |
| 正式课堂 | 页面与语音同步推进，能完成讲解和互动练习，内容遵循既定知识结构。 |
| 过程调整 | 连续答对或出错能够影响后续教学内容与难度，并保持教学目标。 |
| 打断与恢复 | 当前知识问题答疑后回到原位置；后续知识和偏题问题分别按既定方式处理。 |
| 自由探索 | 简单问题得到简答，系统性需求形成可滚动、回看和追问的微课程。 |
| 实践学习 | 学生可完成与知识点相关的实验，结果写入学习状态。 |
| 跨场景个性化 | 某场景产生的学习证据能够影响其他场景中的教学或推荐。 |
| 学习路径 | 能依据掌握情况减少重复、补充前置知识或安排复习。 |
| 内容可靠性 | 正式课程核心内容有知识库依据，核心练习与答案具备审核或校验依据。 |

## 10. 赛事对应与待明确事项

### 10.1 方案对应方向

方案规划的对话答疑、教学课件、编程实践和游戏化练习可对应赛事中的相关交互类别。最终参赛版本需要按 [赛题要求](competition.md) 检查实际完成情况，不能仅凭规划认定已满足至少三类要求。

### 10.2 待明确事项

以下内容需在需求对齐时明确：

- 首个可运行版本的学段、课程、知识点、练习类型与实验范围。
- 学段选择或教材选择的具体入口，以及教材和课程知识库的来源、范围与使用授权。
- 教学材料推荐和视频、Word、PPT 等资源的支持范围；分页课件本身不等同于这些文件格式的支持。
- 在线编程的语言、预置代码框架、运行与调试方式，以及执行安全边界。
- 语音、图像和模型服务的选择，以及响应时间、使用成本和部署目标。
- 学习状态更新、掌握程度判断、补充学习和复习安排的判定标准。
- 面向未成年学生的数据收集范围、隐私保护和教学内容安全要求。

赛事要求的系统原型、集成部署说明和参赛报告等交付物统一见赛题文档；本文不展开开发任务规划。
